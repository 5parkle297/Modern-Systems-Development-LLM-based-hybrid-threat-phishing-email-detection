# 第二章 技术路线与系统架构设计

## 2.1 技术选型与理论基础

### 2.1.1 技术栈选择原则

在构建混合威胁钓鱼邮件检测系统的过程中，技术选型需综合考虑以下核心原则：

（1）**技术成熟度与生态完善性**：优先选择在学术界与工业界广泛验证、具备丰富开源资源与社区支持的技术框架，以降低开发风险、提升迭代效率。

（2）**性能与可扩展性**：系统需具备处理大规模邮件检测任务的能力，技术选型应兼顾推理速度、内存占用、并发处理等性能指标，并预留水平扩展空间。

（3）**可维护性与模块化**：采用前后端分离、微服务化的设计理念，确保各功能模块低耦合、高内聚，便于独立开发、测试与部署。

（4）**成本控制与资源优化**：在保证检测效果的前提下，优化 LLM API 调用成本、计算资源消耗，实现效果与成本的平衡。

### 2.1.2 后端技术栈

**（1）Web 框架：FastAPI**

FastAPI 是一款基于 Python 3.6+ 类型提示的现代化高性能 Web 框架，相比传统 Flask、Django 等框架，具有以下显著优势：
- **高性能**：基于 Starlette 与 Uvicorn，支持异步请求处理（async/await），性能可媲美 Node.js、Go 等语言框架。
- **自动文档生成**：基于 OpenAPI 标准自动生成交互式 API 文档（Swagger UI、ReDoc），降低接口对接成本。
- **类型安全**：利用 Python 类型提示与 Pydantic 库实现请求参数自动校验、序列化与反序列化，减少运行时错误。
- **开发效率**：简洁的路由装饰器语法、依赖注入机制，显著提升开发效率。

**（2）LLM 接口集成：OpenAI 兼容 API**

为实现 LLM 检测模块，本系统采用 OpenAI 兼容 API 接口标准，具体优势包括：
- **统一接口规范**：OpenAI 的 `/v1/chat/completions` 接口已成为事实上的行业标准，主流 LLM 服务提供商（如 SiliconFlow、Together AI、Groq 等）均提供兼容接口，便于模型切换。
- **灵活模型选择**：支持配置不同规模与能力的模型（如 GPT-4、Claude、Qwen、DeepSeek 等），可根据成本与性能需求动态调整。
- **少样本学习能力**：通过精心设计的 System Prompt 与 Few-shot Examples，无需模型微调即可实现有效检测。

**（3）特征提取：Sentence-Transformers 与 Scikit-learn**

- **Sentence-Transformers**：用于将文本转换为稠密向量表示（Embedding），本系统选用 `all-MiniLM-L6-v2` 模型，该模型在平衡速度与效果方面表现优异，适合实时特征提取。
- **Scikit-learn**：用于传统机器学习特征工程，包括 TF-IDF 向量化、统计特征计算等，为规则引擎与传统 ML 模块提供支持。

**（4）检索增强生成（RAG）：LangChain 与 FAISS**

- **LangChain**：轻量级 LLM 应用开发框架，提供文档加载、文本分割、向量存储、检索链等组件，简化 RAG 系统构建流程。
- **FAISS（Facebook AI Similarity Search）**：高效向量相似度检索库，支持十亿级向量的快速近似最近邻搜索，用于品牌模板库、钓鱼模式库的相似度匹配。

**（5）邮件解析：Python email 模块与 mailparser**

- **email 模块**：Python 标准库，用于解析 `.eml` 格式邮件文件，提取邮件头（Header）、正文（Body）、附件（Attachment）等结构化信息。
- **mailparser**：第三方增强库，提供更友好的 API 与更全面的字段解析（如 SPF、DKIM、DMARC 认证结果）。

### 2.1.3 前端技术栈

**（1）前端框架：Vue.js 3**

Vue.js 3 采用 Composition API 设计，具备以下优势：
- **渐进式架构**：既可用于简单的单页应用，也可通过 Vue Router、Vuex/Pinia 构建复杂的企业级应用。
- **响应式系统**：基于 Proxy 的响应式实现，性能优于 Vue 2.x。
- **生态成熟**：丰富的组件库、工具链与社区资源。

**（2）UI 组件库：Element Plus**

Element Plus 是饿了么团队开源的 Vue 3 UI 组件库，提供丰富的表单、表格、对话框、通知等组件，可快速构建美观、交互友好的管理后台界面。

**（3）构建工具：Vite**

Vite 是新一代前端构建工具，相比 Webpack 具有以下优势：
- **快速冷启动**：基于 ES Modules 的开发服务器，无需打包即可运行，启动速度显著提升。
- **热模块替换（HMR）**：增量更新，修改代码后浏览器即时刷新，开发体验流畅。
- **生产优化**：基于 Rollup 的生产构建，支持代码分割、Tree-shaking 等优化。

**（4）HTTP 客户端：Axios**

Axios 是基于 Promise 的 HTTP 客户端，支持请求/响应拦截、自动 JSON 转换、取消请求等功能，便于与后端 API 交互。

### 2.1.4 多模态检测技术储备

针对混合攻击链（邮件文本 + 钓鱼网页截图/仿冒登录页）的检测需求，本系统预留多模态检测模块接口，计划集成以下技术：

**（1）视觉语言模型（VLM）**

- **GPT-4V（Vision）**：OpenAI 发布的多模态大模型，支持图像理解与视觉问答，可用于分析邮件中嵌入的截图或链接指向网页的视觉特征。
- **Claude 3 Opus**：Anthropic 发布的多模态模型，在文档理解、图表分析等任务中表现优异。
- **Gemini Pro Vision**：Google 发布的多模态模型，支持图像、视频、音频等多种输入。

**（2）网页截图获取与分析**

- **Playwright/Selenium**：自动化浏览器工具，用于渲染目标 URL 并获取截图。
- **OCR 技术**：提取网页截图中的文本信息（如品牌名称、表单字段），辅助仿冒检测。

由于多模态检测涉及额外的 API 调用成本与复杂性，本系统设计了可配置的开关（`MULTIMODAL_ENABLED`），在实际部署时可根据需求灵活启用。

### 2.2.3 模块职责划分

**（1）EmailParser（邮件解析器）**

- **输入**：`.eml` 文件或原始邮件文本
- **输出**：结构化邮件数据（JSON 格式）
- **核心功能**：
  - 解析邮件头部字段（From、To、Subject、Reply-To、Date、Message-ID 等）
  - 提取正文内容（优先纯文本，兼容 HTML）
  - 提取所有 URL 并解析域名、路径、查询参数
  - 提取附件元数据（文件名、MIME 类型、大小）
  - 解析 `Authentication-Results` 字段，提取 SPF/DKIM/DMARC 状态

**（2）FeatureExtractor（特征提取器）**

- **输入**：结构化邮件数据
- **输出**：多维度特征字典
- **核心功能**：
  - **文本特征**：字符数、词数、大小写比例、数字比例、特殊字符比例、感叹号/问号计数、可疑短语命中数
  - **URL 特征**：URL 数量、域名类型（IP/域名）、路径长度、查询参数长度、短链接标记、可疑 TLD 标记
  - **Header 特征**：发件人域名与 URL 域名一致性、Reply-To 与 From 一致性、SPF/DKIM/DMARC 状态
  - **Embedding**：使用 Sentence-Transformers 生成文本向量表示

**（3）RuleEngine（规则引擎）**

- **输入**：邮件数据 + 提取的特征
- **输出**：规则检测结果（得分 + 命中规则列表）
- **核心功能**：
  - URL 黑名单匹配（支持域名/IP 黑名单）
  - 可疑短语正则匹配（如 "urgent.*verify"、"account.*suspended" 等）
  - 域名欺骗检测（发件人域名与 URL 域名不一致）
  - 短链接检测（bit.ly、tinyurl.com 等）
  - 可疑 TLD 检测（.tk、.ml、.ga 等免费顶级域名）
  - SPF/DKIM/DMARC 认证失败检测

**（4）LLMDetector（LLM 检测器）**

- **输入**：邮件数据（Subject + Body）
- **输出**：LLM 判别结果（label、confidence、reasoning）
- **核心功能**：
  - 构造结构化 Prompt（System Message + User Message）
  - 调用 OpenAI 兼容 API（支持模型切换）
  - 解析 JSON 格式响应，提取判别标签、置信度与理由
  - 异常处理与降级策略（JSON 解析失败时文本提取）

**（5）RAGRetriever（RAG 检索器）**

- **输入**：邮件文本
- **输出**：相似模板列表（品牌/钓鱼模式）
- **核心功能**：
  - 将邮件文本转换为 Embedding 向量
  - 在 FAISS 向量库中检索 Top-K 相似文档
  - 匹配已知品牌仿冒模板（如 PayPal、Amazon、Bank of America 等）
  - 匹配典型钓鱼话术模式（如账户验证、中奖通知等）
  - 返回相似度分数与匹配内容

**（6）MultimodalDetector（多模态检测器）**

- **输入**：邮件中提取的 URL 列表
- **输出**：多模态检测结果（仿冒网页识别）
- **核心功能**：
  - 使用 Playwright 渲染目标 URL 并截图
  - 调用 VLM（如 GPT-4V）分析截图内容
  - 检测是否为仿冒登录页、品牌冒用等
  - 提取网页中品牌标识、表单字段等关键信息

**（7）EnsembleFusion（集成融合器）**

- **输入**：各模块检测结果
- **输出**：最终判别结果 + 可解释性报告
- **核心功能**：
  - 加权融合各模块得分（权重可配置）
  - 确定最终标签（phishing/suspicious/benign）
  - 计算综合置信度
  - 汇总所有命中规则、LLM 理由、RAG 匹配、多模态发现
  - 生成分级安全建议（如"立即删除"、"谨慎处理"、"可信"等）

## 2.3 核心算法与方法设计

### 2.3.1 LLM Prompt 工程设计

高质量的 Prompt 是 LLM 检测模块的核心。本系统采用结构化 Prompt 设计，包含以下组成部分：

**（1）System Message（系统角色定义）**

```
You are an expert cybersecurity analyst specializing in phishing email detection.
Your task is to analyze the provided email content and determine whether it is:
- "phishing": A malicious email attempting to steal credentials or install malware
- "suspicious": Contains some suspicious indicators but not definitively malicious
- "benign": A legitimate email

Consider the following indicators:
1. Urgency or threatening language (e.g., "account suspended", "verify immediately")
2. Requests for sensitive information (passwords, credit card numbers, SSN)
3. Suspicious URLs or mismatched sender domains
4. Grammar/spelling errors or unusual formatting
5. Generic greetings (e.g., "Dear Customer" instead of name)
6. Offers that seem too good to be true

Respond in JSON format:
{
  "label": "phishing" | "suspicious" | "benign",
  "confidence": 0.0 to 1.0,
  "reasoning": "Brief explanation of your decision"
}
```

**（2）User Message（待检测邮件内容）**

```
Subject: {subject}

From: {from_address}

Body:
{body_text}
```

**（3）Few-shot Examples（可选）**

为提升检测准确率，可在 Prompt 中插入少量标注样本作为示例：

```
Example 1:
Subject: Urgent: Your PayPal Account Has Been Limited
From: security@paypa1-verify.com
Body: Dear Customer, We detected unusual activity. Click here to verify: http://bit.ly/...
Label: phishing
Reasoning: Fake PayPal domain (paypa1 vs paypal), urgent language, shortened URL

Example 2:
Subject: Weekly Team Meeting Notes
From: alice@company.com
Body: Hi team, Attached are the notes from today's meeting...
Label: benign
Reasoning: Internal company email, normal business communication
```

### 2.3.2 集成融合策略

本系统采用加权线性融合策略，综合各模块得分：

**（1）得分归一化**

各模块输出的得分范围可能不同，需归一化至 [0, 1] 区间：
- RuleEngine：已归一化（0 = 正常，1 = 高风险）
- LLMDetector：使用 confidence 值（0-1）
- RAGRetriever：相似度分数（0-1）
- MultimodalDetector：VLM 输出置信度（0-1）

**（2）加权融合公式**

```
final_score = w1 × rule_score + w2 × llm_score + w3 × rag_score + w4 × multimodal_score
```

其中权重配置（可调）：
- `w1 = 0.25`（规则引擎，快速过滤明显特征）
- `w2 = 0.50`（LLM 检测，语义判别核心）
- `w3 = 0.15`（RAG 检索，知识库辅助）
- `w4 = 0.10`（多模态，补充视觉信息）

**（3）标签决策逻辑**

```python
if final_score >= 0.75:
    label = "phishing"
elif final_score >= 0.40:
    label = "suspicious"
else:
    label = "benign"
```

### 2.3.3 可解释性设计

为增强系统透明度与可信度，检测结果包含以下可解释信息：

**（1）规则命中详情**

列出所有触发的规则，例如：
- "检测到黑名单域名：bit.ly"
- "发件人域名与 Reply-To 不一致"
- "SPF 认证失败"

**（2）LLM 推理过程**

展示 LLM 输出的 reasoning 字段，例如：
- "邮件使用紧急语气要求立即验证账户，且包含短链接，疑似钓鱼"

**（3）RAG 匹配结果**

展示知识库中匹配的相似模板，例如：
- "与已知 PayPal 钓鱼模板相似度 92%"

**（4）多模态发现**

## 2.5 安全性与隐私保护设计

### 2.5.1 数据安全

- **上传邮件加密存储**：敏感邮件内容使用 AES 加密存储
- **API 认证**：预留 JWT Token 认证机制（当前为演示系统，未启用）
- **日志脱敏**：日志中不记录完整邮件内容，仅记录特征摘要

### 2.5.2 隐私保护

- **本地化部署**：支持企业内部私有化部署，邮件数据不出企业网络
- **LLM API 隐私**：可配置使用自托管 LLM（如 Ollama + LLaMA）替代云端 API
- **数据留存策略**：检测结果可配置自动过期删除
